# Project architecture

Pomec Technology is an eight-page marketing and enquiry website built with TanStack Start, React 19 and TypeScript. It deploys through Netlify's Vite adapter. There is no application database, payment flow or user authentication.

## Key directories

- `src/routes/`: eight file routes and the root HTML shell; route types are generated by the framework during the platform build.
- `src/components/Pomec.tsx`: shared navigation, original logo, page layouts, informational content, enquiry form and footer.
- `src/data/site.ts`: business title and summary used by root metadata.
- `src/data/seo.ts`: route-specific titles, descriptions, canonical URLs and JSON-LD.
- `src/styles.css`: responsive design tokens, layouts, typography and reduced-motion rules.
- `public/img/`: locally stored free Unsplash illustrative photographs, delivered through Netlify Image CDN.
- `public/__forms.html`: static Netlify form registration; keep all field names synchronized with QueryForm.
- `public/`: logo, sitemap, robots.txt and llms.txt.

## Conventions and decisions

Use semantic headings and accessible labels, clear keyboard focus, native form validation and responsive CSS. Browser APIs run only in event handlers or effects. Keep short enquiry forms on every page. POST URL-encoded form data to `/__forms.html`, check HTTP errors and reject unchanged static registration HTML. Preserve input on errors, disable duplicate pending requests and announce results. Form activation marker is maintained under `.netlify/features/`.

Do not invent prices, certifications, customer testimonials, staff biographies, response guarantees or project counts. Photos are illustrative, never evidence of managed properties. The supplied address is a road-level location; do not invent a street number, pin or opening hours. Official outbound links are resources without implied affiliation. External inbound backlinks cannot be created by editing this website.

Each new page should include substantive visible content and page-specific metadata. Synchronize all canonical and crawler resources if the domain changes. Do not add an og:image; the platform supplies it. Avoid exposing personal enquiry details in logs. Follow run-specific restrictions on builds and validation; this creation run uses source review and platform validation instead of local build commands.
